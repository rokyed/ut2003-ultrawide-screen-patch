# UT2003 Linux configuration patch

This directory is intended to be its **own Git repository**. It contains only scripts and documentation: no game executable, maps, assets, CD key, Linux binary distribution, copied user configuration, or backup. The `.gitignore` allowlists the five files that may be committed. The prior full-game backup was removed from this directory.

## Requirements

- An **existing** Unreal Tournament 2003 installation with the native Linux patch already installed (`System/ut2003-bin`, `System/UT2003.ini`, `System/Default.ini`). This repository does not supply copyrighted game files or the native executable. Install those separately from a source you are authorized to use.
- Python 3, `file`, **32-bit Mesa Zink** and Mesa GLX, **32-bit Vulkan support for your GPU**, **32-bit OpenAL Soft** (`libopenal.so.1`), and a 32-bit `libstdc++.so.5`. Lutris's `Ubuntu-18.04-i686` runtime can supply the latter; an installed system copy works too. For the experimental Zink borderless mode, `xrandr`, `xdotool`, `wmctrl`, and a primary Xwayland output whose resolution matches the game's resolution are required. Gamescope is optional for a native-renderer SDL-backend experiment.

Place `LinuxPatch/` directly inside the UT2003 game directory and run:

```sh
./LinuxPatch/apply.sh
```

Or run `./LinuxPatch/apply.sh --width 2560 --height 1080` to choose a game resolution (`--no-lutris` leaves the Lutris entry alone). Without dimensions it chooses the primary Xwayland output size, falling back to 1280×720 when no display is available. Zink defaults to **windowed SDL mode**, avoiding UT2003's broken exclusive fullscreen (top-left-quadrant clipping). At a resolution matching the primary output, `UT2003_BORDERLESS=1 ./launch-ut2003.sh` opts into KWin borderless fullscreen, but **this stalled during intro precaching on this host**. Other resolutions remain windowed rather than stretching the viewport. Mesa Zink translates the game's OpenGL calls to Vulkan; there is no native Vulkan renderer. Zink inside Gamescope crashed on this host. Working Zink fullscreen, custom-size fullscreen, and a 4:3 menu with ultrawide gameplay have **not** been verified.

The game's `MenuViewport` is set to a 4:3 size (up to the chosen render width), but **this does not reliably letterbox the menu artwork** when UT2003's actual window is ultrawide. The engine may stretch its menu. Automatic 4:3 menus combined with ultrawide gameplay would require a verified UI renderer or mode-switch fix; this patch does not claim to provide it.

For NVIDIA OpenGL, run `./LinuxPatch/apply.sh --native` (optionally with `--width` and `--height`). This changes the renderer marker and requests SDL fullscreen, **which has previously clipped the viewport**; no game binaries change. Gamescope is not launched by default: its Wayland backend crashed on this host. `UT2003_GAMESCOPE_SDL=1 ./launch-ut2003.sh` opts into an unverified native-OpenGL Gamescope SDL-backend test. To temporarily run the installed Zink configuration with NVIDIA OpenGL _without_ changing the INIs, launch with `UT2003_RENDERER=native ./launch-ut2003.sh -opengl -nogamma`; expect a window if the INIs are still configured for Zink.

For sound, the script links the game's `System/openal.so` and `System/libopenal.so` to the host's **32-bit OpenAL Soft**, which can output to PulseAudio/PipeWire or ALSA, instead of the bundled legacy OpenAL that reported no devices. It disables EAX and launches without the old `padsp32` preload. It makes a link to Lutris's 32-bit `libstdc++.so.5` in `System/` if needed, so host audio libraries are not mixed with Lutris's obsolete PulseAudio libraries. To choose a different 32-bit OpenAL Soft library, set `UT2003_OPENAL_SOFT` to its absolute path when applying. No libraries are bundled in Git. Run the script again to reapply the settings after changes to the installation.

The patch retains the game's bundled SDL 1.2 by default: the installed Steam SDL12-compat build ran at smaller window sizes, but **stalled before the menu at 2560×1080**. For a separate, reversible input experiment at smaller sizes, `./LinuxPatch/apply.sh --sdl-compat --width 1280 --height 720` links to the installed 32-bit Steam SDL12-compat/SDL2 libraries, saving the original SDL in `Backup/libSDL-1.2.so.0.original` outside Git. `--restore-sdl` restores the bundled library. Do not use SDL12-compat as the default ultrawide fix.

When `Escape=ShowMenu` is the existing binding, the patch changes it to `Escape=SetRes <width>x<height>w|OnRelease ShowMenu`. **This is experimental**: a `SetRes` command executes on key-down and may cause a resize or stall even when the dimensions do not change. A release command needs a preceding key-down command in this engine, but this binding has not been verified to eliminate double activation inside menus. It leaves other custom bindings untouched. The active and installed `User.ini` files are backed up under `Backup/`; `./LinuxPatch/apply.sh --restore-input` restores **only the Escape bindings** without overwriting newer controls. Use `--no-input-fix` to leave bindings unchanged on a subsequent application. The key's effect inside every menu still needs an in-game check; this change cannot guarantee that a GUI's own keyboard handling does not also act on Escape.

Before the first application, the script saves each INI, any original `System/openal.so` and `System/libopenal.so`, and any existing launcher **outside `LinuxPatch`**, next to the original with `.pre-linuxpatch` appended. Renderer selection and chosen dimensions are stored as small text markers in `System/` (outside Git). If Lutris needs to be changed, `configure.py` likewise saves a `.pre-linuxpatch` copy of its YAML in your Lutris config directory. The Git repository never contains these private backups, CD keys, or game libraries.

To undo **just the OpenAL library replacement**, run `./LinuxPatch/apply.sh --restore-audio`. Restore other settings from their `.pre-linuxpatch` copies if needed. An earlier bounded desktop launch confirmed `ALAudio: subsystem initialized` with OpenAL Soft 1.24.2. A later bounded 2560×1080 Zink windowed launch on this host stalled at `Init: Name subsystem initialized`; it did not establish that the menu is currently reachable. The log also reports `Sound is too short for streaming: ..\\Music\\KR-UT2003-Menu.ogg`, so menu music may still be missing even if game sound effects work. Audio output cannot be heard or confirmed by this patch script; test it in-game. The bounded launch stops the game with a signal after the test period.
